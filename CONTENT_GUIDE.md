# Как наполнять портфолио своими работами

## Новый формат: свободный порядок медиа и текста

Новые работы создавайте в `.mdx`. Все существующие работы и шаблоны переведены в этот формат.
Главный пример для копирования: `src/content/projects/demo-game-prototype.mdx` — в нём есть все поддерживаемые медиаблоки и вставки.
Старые `.md` также поддерживаются в прежнем режиме; переименовывать свои будущие файлы задним числом не обязательно.

В единственном верхнем блоке между `---` укажите `mediaLayout: "inline"`.
Там же остаются списки gallery, videos, models, audio, codeSamples, downloads и links.
Ниже второго `---` пишите текст и вставляйте компоненты в любом порядке:

```mdx
<Video index={1} open />

Моё объяснение видео.

<Image index={1} open />

Рассказ о картинке.

<Code index={1} />

Объяснение алгоритма.
```

Импорты добавлять не нужно. Нумерация начинается с **1** и относится к соответствующему списку в верхнем блоке.

| Вставка | Какие данные использует |
| --- | --- |
| `<Video />` | Все videos |
| `<Image index={1} />` | Первую картинку из gallery; cover не считается |
| `<Gallery />` | Все gallery |
| `<Models />` | Все models |
| `<Audio />` | Все audio |
| `<Code />` | Все codeSamples |
| `<ShaderGraph />` | Все shaderGraphs: интерактивная структура узлов Unity Shader Graph |
| `<Downloads />` | Все downloads |
| `<Links />` | Все links |
| `<Resources />` | Downloads и links вместе |

`index={2}` выбирает второй элемент. `indices={[3, 1]}` выбирает третий и первый в таком порядке.
Для Resources выбор номера не предусмотрен: используйте Downloads или Links отдельно.
`open` делает внешнюю секцию раскрытой по умолчанию. Сохранённое состояние браузера имеет приоритет.

### Текст слева, медиа справа

Добавьте `group` к любой медиавставке в `.mdx` с `mediaLayout: "inline"`:

```mdx
## Как устроен эффект

Мой рассказ о видео. Здесь могут быть несколько абзацев, список или цитата.

<Video index={1} group open />
<ShaderGraph index={1} group />
```

Текст непосредственно перед вставкой, включая ближайший заголовок, окажется
слева. Медиа — справа. Сбор текста останавливается на предыдущем медиаблоке,
горизонтальном разделителе `---` или другом JSX-компоненте.
Несколько вставок с `group` подряд образуют одну общую колонку медиа
(без автоматической смены кадров, чтобы видео, код и граф оставались управляемыми).
Новый текст после группы начинает следующую группу. Если текста перед вставкой
нет, медиа занимает всю ширину — пустой колонки не будет.
На экранах до 800 px текст идёт сверху, медиа снизу.

Несколько `<Video index={1} group open />`, `<Video index={2} group open />`
подряд автоматически объединяются в одну горизонтальную видеогалерею.
Можно также написать `<Video indices={[1, 2]} group open />`.
Листайте стрелками, свайпом или стрелками клавиатуры, когда галерея в фокусе.
Воспроизводится только центральное видео (автовоспроизведение зависит от политики браузера;
для надёжного старта используйте `muted: true`). На компьютере управление плеером
скрывается без наведения, на сенсорном устройстве используется нативное управление.
Без `group` сохраняется обычное расположение. `group={false}` выключает группировку.

Индивидуальные модели и фрагменты кода сохраняют собственное сворачивание внутри секции.

Без вставки блок не появляется на странице при `mediaLayout: "inline"`; при этом его данные продолжают участвовать в карточках и превью направлений.
Один и тот же блок можно вставить несколько раз, но обычно достаточно одного.
У повторных вставок независимое состояние сворачивания.
Если нужный список пуст, компонент ничего не показывает.
Для прежнего автоматического порядка используйте `mediaLayout: "auto"` и уберите ручные вставки.

Чтобы скопировать пример в другую работу, переносите **и вставку**, и соответствующие данные верхнего блока.
Смените пути, подписи и дату. Удалите чужие демонстрационные cover и gallery, если своих картинок пока нет.
Не создавайте второй блок `--- videos: ... ---` посреди текста.

В MDX комментарии в тексте выглядят как `{/* пояснение */}`, а внутри верхних настроек — как `# пояснение`.
Фрагменты программного кода с фигурными скобками помещайте в codeSamples или тройные обратные кавычки.
В обычном тексте символы `<` и `{` имеют специальное значение; оформляйте их как код, если показываете буквально.

Ниже — справочник настроек и файлов. Примеры верхнего YAML-блока применяются и к `.mdx`.

Руководство именно для этого сайта. Новые библиотеки устанавливать не нужно.
Для обычного наполнения достаточно редактора кода, Проводника и файлов проекта.
Все пути ниже указаны относительно папки `Portfolio Site`.

## 1. Как всё устроено

Язык при первом посещении выбирается по первому подходящему языку браузера (EN или RU),
сохраняется и может быть изменён переключателем.

Для языковых версий медиа положите рядом два файла с одинаковым расширением:
`example_ENVer.webp` и `example_RUVer.webp` (аналогично для видео и аудио).
В проекте достаточно указать один из них. Пара определяется при сборке сайта;
на странице и в карточках выбирается версия текущего языка. Если пары нет,
используется указанный файл. После добавления пары нужна новая сборка/публикация.

Для периода работы оставьте начало в `date` и добавьте необязательное `dateEnd`:

```yaml
date: 2024-05-01
dateEnd: 2025-08-01
```

На карточке и странице появится «май 2024 – август 2025» (с учётом выбранного языка).
Временная линия и сортировка используют только первую дату.
Без `dateEnd` отображается одна дата, как раньше. Дата окончания не может быть раньше начала.

Одна работа — один файл `.mdx` в любой папке внутри `src/content/projects/`.
Сайт сам создаёт страницу, карточку в каталоге и запись на временной линии выбранного направления.
Вручную добавлять ссылки в каталог или рисовать временную линию не нужно.

Файл проекта состоит из двух частей:

1. Между двумя строками `---` — настройки в формате YAML: название, дата, изображения, медиа.
2. Ниже второго `---` — свободный текст в формате Markdown: рассказ о работе.

Настройки отвечают за готовые блоки сайта, Markdown позволяет менять структуру рассказа.
Все медиаблоки необязательны: нет данных — нет соответствующего раздела.
Один проект может одновременно содержать картинки, модели, видео, звук, код и ссылки независимо от направления.

| Взять чистую основу | `templates/project-minimal.mdx` |
| Взять примеры всех медиаблоков | `templates/project-full.mdx` |

| Названия, описания, порядок направлений | `src/data/directions.ts` |
| Обложки, галерея, постеры видео | `public/projects/.../имя-работы/` |
| Модели, миниатюры моделей, видео, звук, архивы | `public/projects/.../имя-работы/` |
| Общие цвета, шрифты, переменные оформления | `src/styles/global.css` |
| Разметка главной | `src/pages/index.astro` |
| Общая разметка всех страниц работ | `src/pages/projects/[...id].astro` |
| Общая разметка страниц направлений | `src/pages/directions/[slug].astro` |
| Каталог всех работ | `src/pages/projects/index.astro` |

`dist/` — результат сборки, его не редактируют: изменения пропадут при следующей сборке.
`node_modules/` и `.astro/` — служебные папки. Для наполнения они не нужны.
Все локальные медиа лежат внутри `public/projects/`. Папки можно вкладывать друг в друга так же, как папки проектов в `src/content/projects/`.

## 3. Первая настоящая работа: пошагово

Пример: вы хотите показать модель рабочего стола.

1. Откройте всю папку `Portfolio Site` в редакторе кода.
2. Скопируйте `templates/project-minimal.mdx` в `src/content/projects/`.
3. Переименуйте копию в `worktable.mdx`. Убедитесь, что это не `worktable.mdx.txt`.
4. Вставьте свои данные вместо примеров:

```yaml
---
title: "Worktable"
mediaLayout: "inline"
summary: "A game-ready worktable modeled and textured in Blender."
direction: "3d-modeling"
date: 2026-10-13
tags: ["Blender", "Game Asset", "Texturing"]
draft: true
demo: false
---

## About the project

I created this worktable as a real-time environment asset.

## My contribution

- Modeling and UV unwrapping.
- Materials and presentation.
```

5. Поставьте настоящую дату работы. Это может быть дата завершения, а не загрузки на сайт.
6. Создайте `public/projects/worktable/` и положите туда обложку `cover.webp`.
7. Перед вторым `---` добавьте строку:

```yaml
cover: "projects/worktable/cover.webp"
```

8. Если хотите показать эту картинку и внутри страницы, добавьте галерею из раздела 7 и вставьте `<Gallery />` между абзацами после второго `---`. Обложка сама в галерею не добавляется.
9. Для модели создайте `public/projects/worktable/` и положите туда `model.glb`.
10. Перед вторым `---` добавьте:

```yaml
models:
  - title: "Worktable"
    description: "Game-ready model with UVs and materials."
    kind: "glb"
    src: "projects/worktable/model.glb"
    autoRotate: true
```

11. После второго `---` вставьте `<Models />` на нужном месте рассказа. Для просмотра временно поменяйте `draft: true` на `draft: false`, сохраните файл.
12. Запустите `server.bat`, выберите `1`. Откройте адрес, который сообщил сервер, обычно `http://localhost:4321/Portfolio-Site/`.
13. Откройте Projects или направление 3D Modeling. Прямой адрес: `http://localhost:4321/Portfolio-Site/projects/worktable/`.
14. Проверьте карточку, рассказ и модель. Сохранения файлов обычно видны в локальном браузере автоматически.
15. Если проект пока не готов к публикации, верните `draft: true` перед отправкой изменений на GitHub.

Имя файла формирует адрес. Название `title` можно менять свободно; переименование `worktable.mdx` изменит ссылку на проект и сломает старые закладки.
Используйте для имён файлов и папок латиницу нижнего регистра, цифры и дефисы: `robot-arm`, `ambient-track-01`.
В простых примерах файл лежит непосредственно в `src/content/projects/`, но вложенные папки полностью поддерживаются. Например, `src/content/projects/Shaders/IsLands/clouds.mdx` создаст страницу `/projects/shaders/islands/clouds/`.

## 4. Как пользоваться полным шаблоном

`project-full.mdx` — конструктор из необязательных блоков.
Скопируйте его в папку проектов и замените `my-project` на своё имя во всех используемых путях.
Примеры медиа начинаются с `#`: в верхней YAML-части это комментарий, сайт его игнорирует.

Чтобы включить блок, удалите первые два символа `# ` у каждой его строки, сохранив остальные пробелы.
Например:

```yaml
# gallery:
#   - image: "projects/my-project/render.webp"
#     alt: "Описание"
```

превращается в:

```yaml
gallery:
  - image: "projects/my-project/render.webp"
    alt: "Описание"
```

Сначала добавьте настоящий файл, затем включайте ссылку на него.
Необязательный `poster` тоже удалите или оставьте закомментированным, если картинки ещё нет.
Ненужные блоки можно целиком удалить. Не оставляйте пустое `gallery:` — удалите строку или напишите `gallery: []`.
Не создавайте второй ключ `gallery:` или `models:`: добавляйте элементы через ещё одну строку `- ...` внутри существующего списка.

## 5. Справочник основных параметров

| Параметр | Обязателен | Что делает |
| --- | --- | --- |
| `title` | Да | Заголовок страницы и карточки |
| `mediaLayout` | Нет | `inline` — ручные вставки между абзацами в MDX; `auto` — прежний автоматический порядок |
| `summary` | Да | Краткий текст карточки, описание страницы и текст для поиска |
| `direction` | Да | Единственное основное направление проекта |
| `date` | Да | Дата `ГГГГ-ММ-ДД`; влияет на хронологию и сортировку |
| `tags` | Нет | Список тегов; участвует в поиске и подборе похожих работ |
| `cover` | Нет | Обложка карточки; без неё будет текстовая заглушка |
| `draft` | Нет | По умолчанию `false`; `true` исключает страницу и карточки |
| `demo` | Нет | По умолчанию `false`; `true` ставит метку Demo и запрет индексации страницы |
| `featured` | Нет | Пока зарезервирован: текущий интерфейс его не использует |

`demo: true` НЕ скрывает работу. Чтобы убрать тестовые проекты из сайта, поставьте им `draft: true`.
Черновики сейчас скрыты и локально. Для визуальной проверки временно используйте `draft: false`.
Даже скрытый проект проходит проверку структуры: неправильный YAML или отсутствующая картинка может остановить сборку.
Черновик — не приватное хранилище: исходники видны в публичном GitHub, а содержимое `public/` копируется в сайт независимо от `draft`.

### Допустимые направления

| Значение `direction` | Раздел |
| --- | --- |
| `game-development` | Игры |
| `3d-modeling` | 3D-модели |
| `music-sound` | Музыка и звук |
| `drawing` | Рисунок |
| `video-editing` | Видеомонтаж |
| `motion-design` | Моушн-дизайн |
| `animation` | Анимация |
| `shading` | Шейдеры и материалы |

Название можно писать на русском или английском; техническое значение `direction` копируйте точно из таблицы.
Интерфейс и язык страниц сейчас английские: русский текст отображается, но полноценное переключение языков не реализовано.

## 6. Единый путь к любому файлу проекта

Для `cover`, `gallery.image`, `videos.poster`, `models.src`, `models.poster`,
`videos.sources.src`, `audio.sources.src`, `downloads.file` и `shaderGraphs.src`
используйте одно правило: путь начинается с `projects/` и повторяет вложенность внутри `public/projects/`, например `projects/Shaders/IsLands/имя-проекта/имя-файла`.
Сам файл положите по соответствующему пути внутри `public/projects/`.

```yaml
src: "projects/worktable/model.glb"
```

Реальный файл: `public/projects/worktable/model.glb`.
Для изображения точно так же: `image: "projects/worktable/render.webp"`.
Внутри папки проекта можно создавать подпапки, например `projects/worktable/images/front.webp`.
Astro продолжает оптимизировать обложки, галерею и постеры видео автоматически.
Сайт проверяет существование локальных файлов и не разрешает выход за пределы public,
`..`, абсолютные пути, обратные слеши и специальные URL-символы в локальных путях.
Не пишите `public/`, диск `C:`, обратные слеши `\` или `/Portfolio-Site/`: компоненты сами добавляют префикс сайта.
Регистр важен: `Worktable.glb` и `worktable.glb` на GitHub Pages — разные имена.
Внешние прямые HTTPS-адреса поддерживаются для видео, аудио, моделей и постеров моделей. Для моделей внешний сервер должен разрешать CORS.
В `downloads.file` используйте локальный путь; внешние скачивания оформляйте через `links`.

## 7. Картинки и галерея

### Исключить определённое медиа из карточек

Внутри нужного элемента `gallery`, `videos`, `models`, `codeSamples` или
`shaderGraphs` добавьте `showInCards: false`. На странице проекта этот элемент
останется; из фонового слайд-шоу карточек проекта и категории исчезнет.
Без параметра всё показывается. Сейчас существующие медиа не скрыты.

```yaml
videos:
  - title: "Дополнительная демонстрация"
    showInCards: false
    sources:
      - src: "projects/my-project/details.mp4"
        type: "video/mp4"
```

Для отдельного поля обложки используйте `coverShowInCards: false` в верхних
настройках проекта. Если та же картинка включена в `gallery`, её элемент
нужно скрыть отдельно. Аудио и скачивания и без того не служат визуальным фоном.
Shader Graph теперь автоматически участвует в слайд-шоу: лёгкая схема узлов
создаётся при сборке, без загрузки интерактивного просмотрщика на карточках.

```yaml
gallery:
  - image: "projects/worktable/front.webp"
    alt: "Wooden worktable viewed from the front"
    caption: "Final front view."
  - image: "projects/worktable/detail.webp"
    alt: "Close-up of the worn tabletop edges"
    caption: "Material detail."
```

`image` и `alt` обязательны. `alt` описывает изображение для тех, кто не может его увидеть; это не имя файла.
`caption` — необязательная видимая подпись. Порядок элементов определяет порядок изображений.
Начните с JPG, PNG или WebP. Практический ориентир для обычной галереи — 1600–2400 пикселей по длинной стороне; это не ограничение сайта.
Для прозрачности используйте PNG или WebP. Сохраняйте исходники высокого разрешения отдельно.

## 8. 3D-модели

```yaml
models:
  - title: "Worktable"
    description: "Low-poly prop with a baked normal map."
    kind: "glb"
    src: "projects/worktable/model.glb"
    poster: "projects/worktable/model-preview.png"
    autoRotate: true
```

`title` — название в свёрнутой карточке. `description` — краткое описание.
Для своей модели всегда указывайте `kind: "glb"` и `src`; если не написать kind, по умолчанию включится демонстрационная фигура.
`poster` необязателен. Без него миниатюра строится из модели при подготовке раздела; это требует загрузить модель.
Готовый PNG с прозрачным фоном позволяет показать миниатюру без предварительного рендера модели. Положите его в `public/` по указанному пути.
`autoRotate: true` включает начальное вращение; взаимодействие с камерой останавливает его.
Для нескольких моделей повторите элемент начиная с `- title:`.

Для первого экспорта выбирайте в Blender формат glTF 2.0, вариант GLB, с материалами и текстурами внутри файла.
Процедурные материалы Blender могут потребовать запекания в текстуры: просмотрщик не воспроизводит произвольные узлы Blender.
Не включайте Draco/KTX2-сжатие: декодеры для этих вариантов сейчас не подключены.
Для UV checker нужна UV-развёртка. Анимация появится только при наличии экспортированных клипов.
Вариант `.gltf` также может загрузиться, но требует сохранить рядом все связанные `.bin` и текстуры с правильными относительными путями; GLB проще переносить.
Если модель не видна, сначала проверьте имя, расширение и путь, затем экспорт и сообщения консоли браузера.

## 9. Видео

```yaml
videos:
  - title: "Worktable breakdown"
    caption: "Modeling and texturing process."
    poster: "projects/worktable/video-poster.webp"
    preload: "metadata"
    loop: false
    muted: false
    sources:
      - src: "projects/worktable/breakdown.mp4"
        type: "video/mp4"
```

`title` и хотя бы один `sources` обязательны. `caption` и `poster` можно удалить.
`preload`: `none` — не запрашивать предварительную загрузку; `metadata` — только служебные данные; `auto` — разрешить более полную загрузку. Браузер может изменить это поведение.
`loop` повторяет ролик, `muted` задаёт начальное отключение звука.
`autoplay: true` запускает видео при раскрытии раздела Video, в том числе если раздел восстановлен раскрытым из памяти браузера. Для надёжного автозапуска также укажите `muted: true`. По умолчанию autoplay выключен.
`autoAspect: true` подстраивает высоту плеера под исходное соотношение сторон видео (например, вертикальное или квадратное). `autoAspect: false` оставляет фиксированную рамку 16:9 с полями при необходимости; это значение по умолчанию. До получения метаданных при автоматическом режиме используется временная рамка 16:9.
При закрытии раздела или уходе в скрытую вкладку видео приостанавливается. Браузер может блокировать автозапуск своими настройками; в этом случае остаётся обычная кнопка Play.
Поддерживаемые MIME-типы в настройках: `video/mp4`, `video/webm`.
В один список sources можно добавить альтернативные кодировки одного ролика; для другого ролика нужен новый элемент videos.
Контейнер MP4 сам по себе не гарантирует воспроизведение: проверьте экспорт в целевых браузерах.
Ссылка на страницу YouTube не является видеофайлом — добавляйте её в `links`, а не в sources.

```yaml
downloads:
  - label: "Download project files"
    file: "projects/worktable/source.zip"
    description: "Model and textures."
    format: "ZIP"
    size: "12 MB"
links:
```

Для downloads обязательны `label`, `file`, `format`; `size` — ручная подпись, сайт не измеряет размер.

## 12. Код с подсветкой и копированием

```yaml
codeSamples:
  - title: "Clamp a value"
    filename: "math.ts"
    language: "ts"
    description: "Keeps a value inside a range."
    code: |
      export function clamp(value: number, min: number, max: number) {
        return Math.min(max, Math.max(min, value));
      }
```

Обязательны `title`, `filename`, `language`, `code`. Filename — подпись, отдельный файл с этим именем создавать не нужно.
Символ `|` означает многострочный текст. Все строки кода должны оставаться глубже строки `code:` по отступам.
Языки: `astro`, `bash`, `cpp`, `csharp`, `css`, `glsl`, `hlsl`, `shaderlab`, `html`, `js`, `json`, `plaintext`, `python`, `ts`.
Для Unity-файла `.shader` укажите `language: "shaderlab"`, для отдельного HLSL-кода — `"hlsl"`.
Подсветка выбирается по language, а не по filename. Вставьте настоящий исходник после code: |, сохранив отступы.
Каждый фрагмент кода раскрывается отдельно нажатием на его заголовок; по умолчанию закрыт, состояние сохраняется в браузере.
В карточках проектов и направлений код автоматически участвует в смене фоновых медиа с подсветкой выбранного языка. Превью показывает первые 28 строк, полный исходник доступен в разделе Code страницы работы.
Чтобы убрать демонстрационную обложку из новой работы, удалите строку cover. Не оставляйте cover пустым.
Превью продолжит показывать собственную галерею, видео и модели работы.
Код здесь показывается как текст, а не запускается в браузере. Не вставляйте пароли и ключи доступа.

## 13. Рассказ о работе: Markdown

### Интерактивный Shader Graph

Положите файл `.shadergraph` или `.shadersubgraph` в папку работы внутри `public/projects/` и добавьте в верхний блок:

```yaml
shaderGraphs:
  - title: "My Shader Graph"
    src: "projects/my-project/example.shadergraph"
    description: "Nodes, connections and exposed properties."
```

Затем вставьте между абзацами `<ShaderGraph index={1} open />`.
Просмотрщик загружается только при раскрытии секции. Есть масштабирование колёсиком, перемещение перетаскиванием, Fit graph, Properties, Inspector, Fullscreen.
Open viewer открывает граф отдельно, Download graph скачивает оригинал.
Файлы остаются на нашем сайте; сторонние сервисы не используются. Структура графа отображается, но результат исполнения Unity-шейдера не рендерится: показывайте эффект через видео.
Перемещение узлов не изменяет исходный файл. Текстуры Unity по GUID не восстанавливаются; подграфы нужно добавлять отдельными файлами и отдельными вставками.
Проверен SettPreviewShad.shadergraph (формат SGVersion 3); новые версии Unity и незнакомые узлы могут потребовать адаптации.
В карточках по-прежнему используются видео, картинки, модели и подсвеченный код; интерактивный граф доступен на странице работы.

После второго `---` пишите свободно. Не нужно сохранять все заголовки шаблона.

````markdown
## Задача

Обычный абзац. **Жирное выделение**, *курсив*, `название функции`.

Следующий абзац отделён пустой строкой.

## Что я сделал

- Моделирование.
- Текстурирование.

## Этапы

1. Исследование.
2. Прототип.
3. Финальная версия.

> Короткая заметка.

[Внешний источник](https://example.com)

```ts
const result = 42;
```
````

Начинайте с `##`: главный заголовок уже формируется из title.
Заголовки, списки и абзацы можно добавлять, удалять и переставлять.
Для картинок проще пользоваться gallery: там уже есть оптимизация и просмотр увеличенного изображения.
Обычные Markdown-ссылки на внутренние страницы не получают префикс автоматически: используйте, например, `/Portfolio-Site/projects/worktable/`.
При `mediaLayout: "inline"` медиаблоки показываются на местах компонентных вставок в тексте. Порядок ключей YAML не влияет на порядок вставок.
При `mediaLayout: "auto"` действует прежний порядок: галерея, модели, видео, аудио, ресурсы, код, затем рассказ.

## 14. Частые ошибки YAML

- Используйте пробелы, не Tab. В примерах один уровень — два пробела.
- После `:` нужен пробел: `title: "Worktable"`.
- Текст удобно всегда заключать в прямые кавычки `"..."`, особенно если в нём есть двоеточие или `#`.
- Для текста с двойными кавычками можно использовать внешние одинарные: `title: 'Model "Workshop"'`.
- `true` и `false` пишите без кавычек: это логические значения, не текст.
- Дата: `2026-10-13`, а не `13.10.2026`.
- Не дублируйте ключи одного уровня. Несколько картинок — один gallery со списком.
- Удаляйте весь ненужный блок, а не только его вложенные строки.
- В верхней части `#` — комментарий; в нижней Markdown-части `##` — заголовок.

## 15. Главная, контакты и направления

### Тексты главной

Откройте `src/data/home.ts`. Меняйте только значения; сохраняйте запятые, кавычки и скобки.
`name` — крупное имя, `alias` — строка под ним, `eyebrow` — надпись Portfolio website.
`aboutPreview` — краткое описание; каждый элемент `aboutParagraphs` — отдельный абзац раскрытого текста.
Можно добавить третий абзац строкой в массиве. HTML в этих строках не нужен: он будет показан как текст.
`pageTitle` — название вкладки главной, `pageDescription` — её описание для поисковиков.
Остальные поля подписаны по секциям: directions, contact, readMore, showLess.
Эти настройки относятся к главной; бренд в шапке, подпись подвала и метаданные других страниц пока задаются в соответствующих файлах отдельно.

### Контакты

В `src/data/contactLinks.ts` скопируйте один объект внутри массива и заполните:

```ts
{
  label: "Email",
  detail: "your-name@example.com",
  description: "For collaboration and project inquiries.",
  href: "mailto:your-name@example.com",
  icon: "mail",
},
```

Это пример: замените адрес настоящим. Для соцсетей используйте полный `https://...`.
`label` — название, `detail` — короткая подпись, `description` — пояснение, `href` — адрес, `icon` — имя существующей иконки.
Имена иконок перечислены в `src/data/icons.ts`; для обычной ссылки подходит `external-link`.
Удаление объекта из массива убирает контакт. Перестановка объектов меняет порядок.

### Направления

В `src/data/directions.ts` можно менять title, description, icon и порядок объектов directions.
Существующий slug лучше сохранять: это адрес страницы и значение, которое используют проекты.
Если добавляете новое направление, добавьте его slug и в directionSlugs, и в объект массива directions. Отдельную страницу создавать не нужно.
Если удаляете направление, сначала перенесите все использующие его проекты в другое.
При изменении числа направлений поправьте фразу с их количеством в `home.ts`.

## 16. Что сайт делает автоматически

Плитки направлений показывают сменяющиеся превью всех опубликованных работ своего направления.
Карточки проектов (включая каталог и похожие работы) показывают только медиа этого проекта:
обложку и галерею без повторного показа той же обложки, затем видео, модели и код с подсветкой.
Медиа служат фоном всей плитки. Первая смена имеет собственную случайную задержку от 1 до 5 секунд для каждой карточки, последующие используют общий интервал MEDIA_INTERVAL_MS в `src/scripts/mediaPreview.ts` (сейчас 5000 мс). Переход длится 1,2 секунды. Кнопок, счётчика и подписей кадров нет.
При уходе за пределы экрана или в скрытую вкладку отсчёт приостанавливается и затем продолжается с оставшегося времени; новая случайная задержка не выбирается.
Следующие кадры подготавливаются заранее; пока тяжёлый файл загружается, сменяются уже готовые изображения.
Видео идут без звука; модели показаны прозрачными статичными миниатюрами без элементов управления 3D.
Если у модели задан poster, используется он; иначе миниатюра создаётся автоматически в браузере.
Для большого количества тяжёлых моделей лучше заранее добавить poster: так не понадобится загружать GLB для карточки.
Вне экрана и в скрытой вкладке смена и видео останавливаются. Фон использует явное плавное растворение кадров длительностью 1,2 секунды.
Для новых проектов дополнительных настроек не требуется. Аудио и скачивания в визуальную ленту не входят.

- Показывает опубликованную работу в общем каталоге и её направлении.
- Расставляет работы по дате на временной линии; новые выше старых, карточки чередуются по сторонам.
- Создаёт отметки годов; расстояния между карточками не пропорциональны числу прошедших дней.
- Даёт искать по названию, краткому описанию и тегам. Длинный Markdown-текст не входит в этот поиск.
- Подбирает до трёх похожих проектов по направлению, тегам и датам.
- Показывает только заполненные медиаблоки.
- По умолчанию сворачивает медиаразделы и запоминает их состояние в браузере посетителя.

Если раздел у вас уже раскрыт, это может быть сохранённое состояние вашего браузера, а не ошибка шаблона.

## 17. Проверка и публикация

1. Сохраните все изменённые файлы.
2. Локально проверьте карточку, текст, медиа, скачивания и внешние ссылки.
3. Убедитесь, что у готовых проектов `draft: false`, а у неготовых — `true`.
4. Откройте терминал в корне Portfolio Site и выполните `npm run build`.
5. Если сборка завершилась ошибкой, прочитайте первую содержательную ошибку: обычно там указан файл и проблемное поле. Исправьте и повторите.
6. После успешной сборки отправьте изменения на GitHub или попросите меня проверить, сделать коммит и отправить.
7. В GitHub откройте репозиторий → Actions → последний Deploy to GitHub Pages. Дождитесь успешного завершения публикации.
8. Проверьте интернет-версию сайта. Локальное сохранение само по себе её не обновляет.

Если отправляете вручную из терминала:

```powershell
git status
git add src/content/projects/worktable.mdx public/projects/worktable
git diff --cached --stat
git commit -m "content: add worktable project"
git push origin master
```

В git add укажите именно существующие файлы и папки своей работы. Если меняли home.ts, добавьте и его.
Перед коммитом проверьте список подготовленных файлов; не включайте случайные личные материалы.
Не отправляйте папку dist вручную: её собирает GitHub Actions.
Если push отклонён из-за новых удалённых изменений, не используйте force — сначала разберите расхождение или попросите меня помочь.
Настройка Pages описана отдельно в [DEPLOYMENT.md](DEPLOYMENT.md).

## 18. Если что-то не работает

| Симптом | Что проверить первым |
| --- | --- |
| Проекта нет в каталоге | Файл в src/content/projects, расширение .mdx или .md, draft: false |
| Страница 404 | Имя файла без расширения в адресе, префикс /Portfolio-Site/, завершение публикации |
| Картинка мешает сборке | Файл действительно существует, путь от файла проекта и регистр совпадают |
| Модель не загружается | src без public/, правильное .glb, текстуры внутри экспорта |
| Модель есть, UV нет | Экспортирована ли UV-развёртка |
| Видео/звук не играет | Это прямой файл, правильный MIME и поддерживаемая кодировка |
| Скачивание даёт 404 | Файл в public по указанному пути; build такие ссылки не всегда проверяет |
| Локально работает, онлайн нет | Регистр имён, файлы отправлены в GitHub, Actions успешно завершён |
| Блок пуст или ошибка данных | Отступы YAML, пустой ключ, забытые кавычки или дубликат ключа |
| Правки текста не видны онлайн | Коммит отправлен, публикация завершена, страница обновлена |

Успешная сборка проверяет структуру и обработку картинок, но не гарантирует исправность всех медиа и внешних ссылок: их нужно открыть.
Дата в подвале берётся из последнего коммита репозитория; она не заменяет проверку успешного deploy в Actions.

## 19. Рабочая привычка для каждой новой работы

Копия шаблона → название и дата → короткое описание → обложка → нужные медиа → рассказ → локальная проверка → сборка → коммит и отправка → проверка онлайн.

Не пытайтесь заполнить все поля ради полноты. Для рисунка часто достаточно галереи и текста, для музыки — аудио и описания, для программы — скриншотов, кода и ссылки, для 3D — рендеров и одной модели.
Сначала оформите одну настоящую работу. Следующие похожие работы можно создавать копированием уже готового файла, проверяя все старые пути, дату и флаг draft.

Техническая основа: [коллекции контента Astro](https://docs.astro.build/en/guides/content-collections/). Для ежедневного наполнения читать документацию Astro не обязательно.
